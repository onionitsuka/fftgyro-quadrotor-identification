# クアッドロータの推進・姿勢応答シミュレーション

卒論「三軸姿勢試験台を用いたクアッドロータの推進・姿勢応答モデルの同定」の付録用コードです。
地上試験から得た保存済み係数を用い、指令・電圧からRPM、6軸荷重、機体運動を計算します。

## ファイル

- `simulate.py`：推進荷重、ホバートリム、モーター応答、剛体運動、制御、時間積分、結果保存。
- `aerodynamics.py`：元の解析から抽出した特徴量の評価。回帰・ログ読込・通信処理を含みません。
- `model.json`：6軸の採用項・係数（2つの学習経路）、モーターマップ、機体諸元、制御設定、計算条件。
- `requirements.txt`：実行・描画・テストに必要なPythonパッケージ。

単独フォルダとして実行でき、元のprivateリポジトリや生データを必要としません。

## コードの取得

リポジトリを取得し、`sim/appendix/` を開いてください。
このフォルダだけを取り出しても実行できます。

## 初めて使う場合

Python 3.11以上を用意し、このREADMEと `simulate.py`、`model.json` があるフォルダで実行します。
付録Cの計算にはUnity・PX4・実験ログは不要です。まずバッチ計算で比較図を作り、必要ならブラウザ操縦を使います。

### macOS / Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python simulate.py --output results/example
.venv/bin/python simulate.py --output results/example --plot-only
```

### Windows（PowerShell）

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe simulate.py --output results/example
.\.venv\Scripts\python.exe simulate.py --output results/example --plot-only
```

`results/example/comparison.png` を開くと、速度・高度・Pitch・前方距離を比較できます。
`existing.csv` と `identified.csv` に時系列、`summary.json` に計算の完了状態を保存します。
再計算時は `results/example2` など別の出力先を指定してください。既存フォルダは上書きしません。
描画だけなら、同じ出力先に `--plot-only` を付けます。

ブラウザ操縦はmacOS/Linuxで `.venv/bin/python interactive.py`、Windowsで
`.\.venv\Scripts\python.exe interactive.py` を実行し、`http://127.0.0.1:8765` を開きます。
終了は実行したターミナルで Ctrl+C です。

## 実行

### ブラウザで自由に操縦する

```sh
python3 interactive.py
```

`http://127.0.0.1:8765` にローカルの操縦画面を開きます。Macでは
`launch-interactive.command`、Windowsでは `launch-interactive.bat` でも起動できます。
依存パッケージは下記のバッチ計算と共通です。ブラウザ以外への通信や実機の操作は行いません。

- 既存モデル / 同定モデル、実測RPM学習係数 / 推算RPM学習係数を選べます。変更時は各モデルのホバー釣り合いから再開します。
- キーボードは W/S 前後、A/D 左右、Q/E 方位、上下キーで上昇下降、P 一時停止、R リセット。
- PSコントローラーはUSB/Bluetoothで接続し、ボタンを一度押してから「コントローラーで操縦する」を選びます。
- プロポはOSからUSBジョイスティックとして見える接続（シミュレーターモードまたは対応アダプター）が必要です。単にUSB設定用端子をつなぐだけでは使えない機種があります。
- Mode 2は左スティックが推力/Yaw、右スティックがPitch/Rollです。USBプロポのチャンネル順は画面の「軸割り当て・反転」で調整します。PS標準配置は軸0=Yaw、1=推力、2=Roll、3=Pitchです。
- **推力の中央はホバー相当、下端はその35%、上端は165%です。停止・始動を扱うスロットル0〜100%ではありません。** 姿勢指令は±25度。Mode 2では位置・高度のフィードバックを使いません。Yawの指令は最大約34度/秒で、離すと方位保持します。速度・高度保持モードにも切替できます。
- PSのボタン9（Options/Start）は一時停止/再開です。画面からフォーカスが外れると一時停止します。
- 風速と風の進む向きを変更できます。設定風へ時定数2秒で近づけます。対気速度11.5 m/s、傾き70度、地面到達などで計算を止め、理由を表示します。
- CSVと計算条件JSONを保存できます。共有サーバー上の1つの機体なので、操縦タブは1つにしてください。

3D表示の機体は見やすさのため2倍の大きさで描画しています。位置・高度・軌跡・グリッドは実寸です。
200 Hz固定刻みで積分し、PCの処理が追いつかない場合は実時間よりゆっくり進みます。
荷重の計算には既存の `simulate.py` / `aerodynamics.py` / `model.json` をそのまま使い、
制御器だけを操縦用の2軸速度・高度・方位指令、または姿勢・推力指令へ拡張しています。
両モデルで制御ゲインとモーター式は共通です。PX4の制御コードやAcroモードではありません。
この操作例だけでモデルの予測精度や制御効果を検証したことにはなりません。

### バッチ計算

Python 3.11以上を使います。下記はこのフォルダをカレントディレクトリとした例です。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python simulate.py --output results/example
.venv/bin/python simulate.py --output results/example --plot-only
```

Windowsでは `.venv/bin/python` を `.venv\Scripts\python.exe` に置き換えます。
`--output` には新しいフォルダを指定します。描画だけの場合は既存の計算結果を指定します。

```sh
python simulate.py --target 5 --output results/forward5
python simulate.py --target 5 --dt 0.0025 --output results/forward5-fine
python simulate.py --route measured --output results/measured-route
```

`--route` は同定荷重の学習経路を選びます。既定の `command_route` は、風洞試験の荷重を指令・電圧から推算したRPMで学習した係数です。
`measured` は同じ荷重を実測RPMで学習した係数です。どちらの場合も、計算中のRPMは指令から生成した値です。

## 計算する飛行

既定例は無風・16 V・初期高度2 mで、2秒ホバー、4秒で目標速度を3 m/sへ上げ、1.5秒保持し、4秒で目標を0へ下げ、3秒停止指令とします。
これは目標値の設定であり、両モデルがその速度に到達することを意味しません。速度追従の良否も出力から確認します。
積分刻みは5 msです。機体FRD・世界NED、quaternionは `[w,x,y,z]` の順です。

計算経路は次のとおりです。

```text
目標速度・高度 → 共通制御器 → 4基の指令
    → 指令・電圧マップ → 一次遅れ → 4基のRPM
    → 既存／同定6軸荷重 → 重心まわりの運動方程式 → 位置・速度・姿勢・角速度
```

各計算ステップでは、計算した機体速度と風速度の差を機体座標へ移して流入を求めます。
同定モデルは各軸1つの関数で、既存モデルの荷重に、風速によらない共通係数の補正項を加えます。
Rollモーメントの補正だけは、風洞でRollの回転運動を与えていないため、機体の90°対称を仮定してPitchモーメントの補正を流用します（入力を機体軸まわりに±90°回したPitch補正の平均）。`model.json` の `roll_transfer` を `false` にすると、風洞データから直接同定したRoll補正に戻ります。
風速による切替や節点補間はありません。

## 初期状態とモデルの比較

両モデルで質量・慣性、モーター特性、制御ゲイン、目標値を共通にします。
初期Roll/Pitchと4基RPMは、それぞれのモデルで重力と荷重が釣り合う解から求めます。
各モデルのトリムに対応する姿勢とモーター配分を、制御器の初期フィードフォワードに用います。
したがって、初期状態とトリム指令まで同一に固定した開ループ比較ではありません。

同定荷重はその時刻の状態だけで決まる絶対値の関数で、初期基準や保存した差分を持ちません。
実測初期荷重を与えず、モデル荷重へmgや定数を足して釣り合いを作る処理も行いません。
回転数二乗成分、重心へのモーメント移送、ローター反作用、ジャイロを含みます。

推進系はKaufmannら（Nature 2023, DOI: 10.1038/s41586-023-06419-4）の式(6)の5項の静特性と、共通時定数55.6 msの一次遅れを使います。係数は機体を三軸姿勢試験台に搭載した無風の回転数試験（2026年11月11日、定常4試験・各モーター60保持区間）から求め、時定数は過渡応答3試験から求めました。純遅延と流入補正は加えていません。

静特性は `n_ss = a0 + a1 V + a2 sqrt(d) + a3 d + a4 V sqrt(d)` です。保存した `coefficients` は電圧を16 Vで割った基底、`coefficients_volts_basis` はこの式の係数です。指令0.30〜0.70、電圧14.07〜16.36 Vで校正しました。停止・始動は検証しておらず、既定例はホバーの釣合いから開始します。
飛行ログから再推定したモーター特性は使っていません。
ローター慣性は別個体の推定値で、近似として残しています。

共通制御器はPX4ではない簡易な速度・高度・姿勢制御器です。
姿勢の帯域は10 rad/s（Yaw 3 rad/s）です。同定モデルは前進時に頭上げモーメントを持つため、帯域が低いと前進できません。
同定モデルが目標速度より遅れるのは、速度制御が抗力を補償していないためです。

## 出力

- `existing.csv`、`identified.csv`：全計算時刻の状態、RPM、指令、6軸荷重、飽和フラグ。
- `config.json`：その計算で使った条件と係数のコピー。
- `summary.json`：完了／途中終了、初期釣合い、最大速度、飽和割合、コードのハッシュ、実行環境。
- `comparison.png`、`comparison.pdf`：速度、高度、Pitch、前方距離の比較。
- `figure_manifest.json`：図の元CSVハッシュ、変換、サイズ、表示条件。

RPMは全区間でシミュレーション生成値です。実測RPMで学習した荷重係数を使うことと、計算中に実測RPMを与えることは異なります。
今回の例は簡易制御器による決定論的な動作例で、PX4 SITLや実飛行の検証結果ではありません。
予測が止まった場合はCSVをその時刻まで保存し、理由を `summary.json` に残します。
11.5 m/sを超える流入や未定義のモデルを外挿して計算を続けることはしません。

## テストとモデルの出典

```sh
python -m pytest -q tests
```

自由落下、ホバー釣合い、角運動量、回転方向、指令遅延、状態に対する荷重評価を検証します。

採用版（2026-11-11）：回転中心94.6 mmでセンサ自己荷重と慣性を再校正し、荷重の帯域を統一して再同定した係数を使用する。風洞・飛行の主評価と同じ版である。飛行データによる係数調整は行っていない。推算経路の係数は、飛行の指令範囲を含む11月11日の校正による回転数から再同定した。実測RPM経路の荷重係数は変更していない。
